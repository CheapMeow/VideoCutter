# VideoCutter

VideoCutter 是一个用 Python 和 Qt 编写的桌面工具，用来裁剪视频并把视频段落拼到轨道上。

## 功能

主界面左侧是素材源，右侧上方是当前帧，右侧下方是视频轨道。窗口底部有一条消息栏，用来显示放入轨道、打开和保存工程，以及输出视频时的结果。

左侧是素材源。点击加号按钮，可以从文件对话框里选择视频并加入素材源。从 Windows 文件浏览器把视频文件拖进左侧窗口，也会把这些文件加入素材源。素材源接受的扩展名包括 mp4、mov、mkv、avi、webm、m4v、wmv、flv、mpg、mpeg、ts。素材栏里的打开、保存、设置和导出是四个同一风格的线框图标。打开是硬碟加上朝内的弧线箭头，保存是硬碟加上朝外的弧线箭头，设置是齿轮，导出是窗口加上朝外的弧线箭头。打开和保存用来读取和保存工程，设置用来选择输出帧率和码率，导出按当前轨道输出视频。每个素材条目的最右端有一个叉，点击后删除这条素材记录。轨道上使用这条素材的片段会一起去掉。在素材列表的空白处按住鼠标左键拖动，会拉出 Windows 选择框，框到的条目都会被选中。先单击一个素材，再按住 Shift 单击另一个素材，会选中这两条以及它们之间的全部素材。素材列表获得焦点后，按 Delete 或 Backspace 会删除当前选中的全部素材条目。这些素材在轨道上的片段会一起去掉。

工程文件的后缀是 vcproj。保存时记录当前轨道正在使用的原素材绝对路径，以及每条轨道上每个片段的时间位置、时长，和这个片段在原素材中的起点。轨道从上到下的顺序会保留。输出视频所依据的那一条原素材也会记下。左侧素材源里还没有放进轨道的文件不会写入工程。打开工程之后，轨道和左侧素材列表按文件中的记录恢复。保存对话框里的文件名会带上 vcproj 后缀。

右侧上方显示当前帧的图像。当前帧由下方轨道里的白色竖线决定，白色竖线所在的时间就是正在显示的帧。多条轨道在这个时间上都有画面时，显示最上面一条轨道的画面。白色竖线没有落在任何段落上时，这里显示“无画面”。

右侧下方是视频轨道。轨道里的视频来自左侧素材源中的文件条目。把左侧条目拖到右下轨道窗口，会在放下的位置生成一段可以操作的视频。第一个放进轨道的视频决定输出视频的宽度和高度。之后拖进轨道的视频，宽高必须和这个尺寸相同。宽高不同的视频不会进入轨道，底部消息栏会写出素材尺寸和轨道输出尺寸。轨道上的段落全部删除之后，下一次放入的视频重新决定输出尺寸。输出帧率和码率在“设置”里分别选择：可以填写指定值，也可以取轨道上各个视频片段的最大值或最小值。默认两项都取最小值。当前选中的那一项带有圆点。没有选中指定值时，对应的数字框是灰色的。指定帧率的单位是帧每秒，指定码率的单位是 kbps。

轨道窗口里有一条白色竖线，表示当前帧所在的位置。

在轨道窗口里滚动鼠标滚轮，可以缩放时间轴。缩放以鼠标所在的时间为中心。缩到最远时，窗口里能看到的时间长度至少是最晚一帧时间的 8 倍。最晚一帧时间是各素材时长和各段落在轨道上的结束时间中更晚的那个。

在上方的时间标尺上单击鼠标左键，或从标尺上按住鼠标左键拖动，当前帧会移到鼠标的水平位置。这次操作从标尺上开始之后，鼠标离开轨道窗口，当前帧仍按鼠标的水平位置更新。鼠标在垂直方向上的移动不改变当前帧。在时间标尺上单击或拖动不会取消轨道上已经选中的视频段落。在轨道区域单击鼠标左键不会改变当前帧。

在轨道区域的空白处按住鼠标左键拖动，可以拖动时间轴。时间轴的左端停在 0 秒。

在视频段落上按住鼠标左键拖动，可以移动这段视频。段落的左侧最多移动到 0 秒，不能再往左。

按住视频段落拖动时，如果鼠标超出轨道窗口的左侧或右侧，时间轴会向相同方向移动。鼠标在窗口右侧外面时，时间轴向更晚的时间移动；鼠标在窗口左侧外面时，时间轴向更早的时间移动，最早停在 0 秒。

同一条轨道上的两个段落不能重叠。正在拖动的段落如果碰到同一条轨道上的其他段落，会停在对方外侧。

两个段落的首尾距离小于吸附阈值时，正在移动的段落会自动吸附到另一个段落上，使这两段的首尾接在一起。吸附看的是正在移动的段落，对所有轨道上的其他段落都生效。吸附阈值是屏幕上的 12 像素，对应的时间长度会随时间轴缩放一起变化，屏幕上的吸附距离保持不变。

轨道窗口获得焦点后，按 S 键，会在当前帧的位置分割当前选中的那一段视频。需要先单击选中轨道上的一段视频，并且当前帧落在这段视频内部。满足这些条件时，只有这一段被分成左右两段。其他轨道上的段落保持原样。当前帧落在段落的首尾端点上时，这一段不会被切开。段落是移动、吸附和避免重叠这些操作的基本单位。

单击一个视频段落会选中它，选中的段落带有白色边框。轨道窗口获得焦点后，按 Delete 或 Backspace 会删除选中的这一段。删除之后，如果这条轨道上已经没有段落，这条空轨道会去掉。左侧素材源里的文件仍然保留。

点击导出图标后，在 Windows 保存对话框里可以选择 MP4、MOV、AVI、WebM。默认选中 MP4，编码是 H.264。MOV 同样使用 H.264。MP4 和 MOV 由 NVIDIA 显卡的 NVENC 硬件编码器编码，需要 NVIDIA 显卡和驱动。AVI 使用 MJPG。WebM 使用 VP9。输出的宽度和高度来自第一个放进轨道的视频。输出帧率和码率来自“设置”，默认取轨道上各个视频片段的最小值。多条轨道在同一时间都有画面时，使用最上面一条轨道的画面。某个时间没有任何段落时，这一帧是黑色。导出过程中，底部消息栏会随着每一帧写出，刷新已完成帧数、总帧数和百分比，并在后面用“小时：分钟：秒/小时：分钟：秒”写出已工作时间和预计工作时间。还没有写出帧时，后半段显示为“—”。写出第一帧之后，预计工作时间按当前速度估计整次导出需要的时间。导出结束后，消息栏显示输出文件路径和这次导出所用的时间。导出过程中，导出按钮变成终止导出。按下后，导出会按关闭程序时的方式立刻停止，已经写出的未完成文件会被删掉，当前界面保留。导出过程中关闭程序，导出会立刻停止，已经写出的未完成文件会被删掉。导出中途出错时，未完成的文件同样会被删掉，消息栏写出失败原因。轨道上没有视频时，底部消息栏会说明无法输出。

轨道窗口可以同时有多条轨道。段落可以左右拖动，也可以上下拖动。把段落拖到某条轨道的画面区域，段落会进入这条轨道。把段落拖到两条轨道之间的空隙、第一条轨道的上方，或最后一条轨道的下方，会在该位置自动新增一条轨道并放入段落，不需要单独创建轨道。拖动结束后，上面已经没有段落的轨道会去掉。轨道数量超出窗口高度时，可以用轨道窗口右侧的垂直滚动条查看。

## 导出速度

导出每一帧时，先按轨道时间找到最上面一条轨道上的素材，再按素材里的显示时间取画面。这一时刻的画面是时间戳不晚于该时刻的最后一帧，见 [src/videocutter/export.py](src/videocutter/export.py:219)。游戏录像的帧间隔不均匀，平均帧率换算出来的帧号会缺号，所以取帧用时间戳。平均帧率只用来决定输出一共有多少帧。

顺序解码。优化前每一帧都先定位再读取。OpenCV 这条路径是 24.7 帧每秒，MP4 和 MOV 的整次导出是 21 帧每秒左右。现在每个素材打开一次，解码线程设为 `AUTO`，见 [src/videocutter/export.py](src/videocutter/export.py:204)。下一次要的画面如果还在后面，就继续往下解码。时间往回跳，或者按素材帧率估算向前超过 240 帧，才重新定位到前面的关键帧，阈值在 [src/videocutter/export.py](src/videocutter/export.py:42)，判断在 [src/videocutter/export.py](src/videocutter/export.py:233)。PyAV 多线程、画面保持 YUV 时，解码是 2953.1 帧每秒。同一条解码再转成 BGR，是 329.4 帧每秒。

画面保持 YUV。把 BGR 转成 yuv420p 测得 218.5 帧每秒，整次导出会被这一步限住。MP4、MOV、WebM 使用 yuv420p。解码帧已经是这个格式时，把 Y、U、V 三个平面复制到编码器自己的帧里，见 [src/videocutter/export.py](src/videocutter/export.py:162)。编码器要改写时间戳和帧类型，解码器后面还要复用原来的帧，所以这里复制一份。素材帧上的关键帧标记会清掉，见 [src/videocutter/export.py](src/videocutter/export.py:117)，否则编码器会在素材的关键帧位置再插入关键帧。AVI 使用 MJPEG，像素格式是 yuvj420p，这时才做格式转换。

MP4 和 MOV 使用 NVIDIA 的 `h264_nvenc`，预设是 `p1`，见 [src/videocutter/export.py](src/videocutter/export.py:46) 和 [src/videocutter/export.py](src/videocutter/export.py:54)。同一段素材上，解码和编码接在一起、画面保持 YUV、码率 12 Mbps：libx264 medium 是 83.9 帧每秒，亮度 PSNR 30.13 dB；`h264_nvenc` p1 是 864.4 帧每秒，PSNR 30.18 dB。p4 是 532.9 帧每秒，p7 是 247.0 帧每秒。p1 速度最高，亮度 PSNR 和 libx264 medium 持平，导出用 p1。AVI 仍用 MJPEG，WebM 仍用 libvpx-vp9。AVI 的提速来自顺序解码和保持 YUV。WebM 的时间几乎都花在 VP9 编码上。

CUDA 解码保持 YUV 是 870.4 帧每秒。画面要从显存复制回内存，比 CPU 多线程的 2953.1 帧每秒慢，导出使用 CPU 多线程解码。多进程把素材分段编码时，libx264 medium 可以从 83.9 帧每秒提到 4 个进程的 173.3 帧每秒。`h264_nvenc` 的编码单元在显卡上是固定的，3 个进程、p4 是 434.4 帧每秒，低于单进程 p1 的 864.4 帧每秒，导出在一个进程里编码。

测速脚本放在 [benchmarks](benchmarks) 目录，在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m benchmarks.methods
.\.venv\Scripts\python.exe -m benchmarks.export_speed
```

两个脚本共用 [benchmarks/source.py](benchmarks/source.py:21) 生成的测试素材：1920×1080、60 帧每秒、20 秒、码率 12 Mbps、每 2 秒一个关键帧的 H.264 视频，画面带有运动和噪点。素材和导出结果写在 `benchmarks/output/`，这个目录已经写在 `.gitignore` 里。测试机器是 AMD Ryzen 9 9950X（16 核 32 线程）和 NVIDIA GeForce RTX 5080（驱动 610.74），PyAV 18.1。

### 整体导出

[benchmarks/export_speed.py](benchmarks/export_speed.py:11) 在一条轨道上放两个各 6 秒的片段，分别取素材的 2 到 8 秒和 12 到 18 秒，共 720 帧，按默认设置导出。输出帧率和码率都取片段的最小值，也就是 60 帧每秒和素材码率。优化前的数据来自提交 `5ef6b55`。那时每一帧都先定位再读取，帧先转成 BGR 数组，MP4 和 MOV 用 libx264 的默认速度档 medium 编码。

| 格式 | 优化前 | 优化后 | 文件大小 |
|---|---|---|---|
| MP4 | 34.15 秒，21.1 帧每秒 | 0.90 到 1.26 秒，571 到 799 帧每秒 | 17.9 MiB |
| MOV | 33.57 秒，21.4 帧每秒 | 0.87 到 0.88 秒，819 到 826 帧每秒 | 17.9 MiB |
| AVI | 27.14 秒，26.5 帧每秒 | 3.20 到 3.46 秒，208 到 225 帧每秒 | 48.6 / 49.8 MiB |
| WebM | 152.62 秒，4.7 帧每秒 | 122.00 秒，5.9 帧每秒 | 14.2 / 14.3 MiB |

优化后的范围来自连续三次测量。MP4 是每次运行导出的第一个文件，会带上 NVENC 初始化的时间。WebM 的时间几乎都花在 libvpx-vp9 编码上。

## 运行

需要 64 位 Windows，以及 Python 3.11 或更高版本。下面的命令使用 Python 3.13，并在仓库根目录执行。

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m videocutter
```

## 打包

打包在 Windows 上进行。环境要求：

- Windows 10 或更高版本
- Python 3.11 或更高版本，建议使用 3.12 或 3.13
- 已用上面的命令安装 `requirements.txt` 里的依赖，其中包含 PyInstaller

打包使用的 Python 解释器通过环境变量 `VIDEOCUTTER_PYTHON` 指定，值是 `python.exe` 的完整路径。本机路径放在 `local/paths.ps1`。这个文件只在本机使用，不会进入版本库。可以把它写成：

```powershell
$env:VIDEOCUTTER_PYTHON = "D:\VideoCutter\.venv\Scripts\python.exe"
```

在仓库根目录执行：

```powershell
. .\local\paths.ps1
.\scripts\build.ps1
```

打包脚本是 [scripts/build.ps1](scripts/build.ps1)。脚本会检查 `VIDEOCUTTER_PYTHON` 指向的解释器至少是 Python 3.11，并且已经安装 PySide6、opencv-python、PyAV 和 PyInstaller。

打包完成后，程序位于 `dist\VideoCutter\VideoCutter.exe`。`build` 和 `dist` 是构建目录，已经写在 `.gitignore` 里。
